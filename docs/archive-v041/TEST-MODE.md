# 테스트 모드 v0.4.1

설정 → 게임 설정 → 테스트 모드를 켠다. 현재 삶의 복사본에서 시작하며 진입 순간 시간이 멈춘다. 화면 오른쪽에 개발 패널과 테스트 배지가 나타난다. 닫기는 패널만 숨기며 배지로 다시 연다. 원본 복원·종료 또는 설정 토글 해제는 진입 전 플레이 상태와 화면 선택을 복원한다.

## 저장과 복구

일반 자동 저장·선택 후 저장·창 종료 저장은 테스트 중 원본 슬롯에 쓰지 않는다. 지금 저장은 테스트 결과를 별도 JSON 파일로 내보낸다. 일반 저장 불러오기·가져오기·이전 삶·새 삶 보관 버튼은 차단한다. 테스트를 끝내기 전에도 기존 저장 파일은 유지된다. 테스트 자체는 브라우저를 닫으면 사라진다.

스냅샷 파일은 현재 상태와 개발 예약 큐를 내려받고 메모리에도 보관한다. 스냅샷 복구는 이 세션에서 마지막으로 만든 스냅샷을 복원한다. 세션 초기화는 테스트 진입 시 상태로 돌아간다. 수치 패널의 실행 취소는 직전 개발 조작을 되돌리며 최대 30단계를 보관한다. 일반 사건 선택을 독립적인 실행 취소 단계로 쌓지는 않는다. 선택 전 스냅샷으로 되돌릴 수 있다.

결과 JSON에는 규칙·콘텐츠 버전, 시드, 상태, 로그, 큐와 예약이 포함된다. 결과 복사는 클립보드 권한이 없으면 파일로 내보낸다. 내려받은 스냅샷을 다시 선택하는 파일 가져오기 UI는 아직 없다. 개발 콘솔에서 테스트 모드를 켠 상태로 아래와 같이 복구할 수 있다.

```js
MurimDev.run('restoreSnapshot', {state: snapshot.state, scheduled: snapshot.scheduled});
```

개발 강제 API는 테스트 모드가 꺼져 있으면 오류를 내며 상태를 바꾸지 않는다. 엔진 내부 개발 연결은 최초 UI 연결 뒤 공개 객체에서 제거한다. 브라우저 개발 콘솔 전체를 보안 경계로 삼는 기능은 아니다.

## 권장 확인 순서

1. 테스트 진입 후 스냅샷 파일을 만든다.
2. 사건에서 검색해 강제 실행하거나 정상 검증을 고른다.
3. 패널이 닫히면 기존 사건/전투 화면에서 선택하고 결과를 확인한다.
4. 테스트 배지 → 로그·큐에서 선택·결과·대기/후속을 확인한다.
5. 수치에서 조건을 조절하거나 다른 시나리오를 생성해 반복한다.
6. 결과를 내보낸 후 원본 복원·종료로 돌아간다.

모든 120종의 268개 선택지는 준비된 성인·자원 맥락에서 저장 복구·결과 단일 확정을 자동 검사했다. 이것은 모든 사건이 일반 플레이에서 자연 도달한다는 증거가 아니다. condition이 false인 사건은 입문·돌파·사망·연쇄 등 예약 전용 경로인지 별도로 확인한다.

신규 가문의 독·암기·진법·개별 가전무공, 배분/항렬, 확장 친족, 개별 무공 XP, 다축 상대 전력, 일반전 독립 사망률은 구현 완료 범위가 아니다.
